# Надёжность: обновление без ошибок у учеников, сторож, копии вне сервера

Всё ниже — один раз, от root на сервере. Потом обновлять сайт одной командой.

## 1. Обновление одной командой (с копией базы и откатом)

```
sh /opt/trainer/deploy/update.sh <SHA>
```

Скрипт делает копию базы, скачивает версию, проверяет её, ставит, перезапускает и ждёт ответа сайта.
Если новая версия не поднялась за 90 секунд, он сам возвращает прежнюю и пишет, что случилось.
Прежний код лежит в `/opt/trainer-prev`.

## 2. Ученики не видят перезапуск (Caddy ждёт, а не отдаёт ошибку)

Откройте `nano /etc/caddy/Caddyfile` и замените строку `reverse_proxy 127.0.0.1:8000` на:

```
	reverse_proxy 127.0.0.1:8000 {
		lb_try_duration 30s
		lb_try_interval 250ms
	}
```

Сохраните: Ctrl+O, Enter, Ctrl+X. Затем выполните `systemctl reload caddy`.
Пока тренажёр перезапускается (~5–10 с), запросы учеников ждут, а не падают с ошибкой.

## 3. Сторож и уведомления о сбоях

```
sh /opt/trainer/deploy/install-reliability.sh
nano /etc/egeshka/alert.conf
```

В `alert.conf` укажите, куда писать (можно и то и другое):

- **Telegram.**
  1. В Telegram напишите @BotFather → `/newbot` и получите токен — это `TG_TOKEN`.
  2. Напишите своему боту любое сообщение.
  3. Откройте `https://api.telegram.org/bot<TG_TOKEN>/getUpdates`, там число `"chat":{"id":…}` — это `TG_CHAT`.
- **Почта.** `ALERT_EMAIL=you@example.ru`. Письмо уходит через ту же почту, что и отчёты учителям (SMTP в private_config.json).

Проверка: `sh /opt/trainer/deploy/alert.sh "проверка связи"` — должно прийти сообщение.

Сторож проверяет сайт каждую минуту:

- не отвечает 3 минуты — перезапускает службу и пишет вам;
- поднялся — пишет «снова работает»;
- предупреждает, если на диске меньше 10% места или копии базы нет больше суток.

## 4. Внешний мониторинг (если упадёт весь сервер)

Сторож живёт на том же сервере: если сервер выключится целиком, он промолчит.
Поэтому заведите бесплатную внешнюю проверку, например UptimeRobot или любой похожий сервис:

- тип — HTTP(s);
- адрес — `https://ВАШ-ДОМЕН/api/health`;
- интервал — 5 минут;
- уведомления — в Telegram или на почту.

Адрес отвечает `{"ok":true,…}`, личных данных в нём нет.

## 5. Копии базы вне сервера (зашифрованные)

Копия каждый день уходит в облако, например на Яндекс Диск. Она зашифрована паролем: без него файл не открыть.

```
apt install -y rclone
rclone config            # n → имя yadisk → тип yandex → дальше Enter; на вопрос про браузер ответьте n
                         # и выполните на своём компьютере (с браузером) команду, которую покажет rclone:
                         # rclone authorize "yandex" — вставьте полученный ответ обратно на сервер
printf 'REMOTE=yadisk:egeshka-backups\nKEEP_DAYS=30\n' > /etc/egeshka/offsite.conf
openssl rand -base64 24 > /etc/egeshka/backup.pass && chmod 600 /etc/egeshka/backup.pass
cat /etc/egeshka/backup.pass     # СОХРАНИТЕ этот пароль у себя (менеджер паролей): без него копии не открыть
sh /opt/trainer/deploy/offsite.sh   # первая копия — проверить, что всё работает
```

Дальше копия уходит каждый день в 10:20 по времени сервера, сразу после обычной копии.

Расшифровка и проверка без изменения рабочего сайта:

```
openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 -in trainer-ВЫБРАННЫЙ.tar.gz.enc -out snapshot.tar.gz -pass file:/etc/egeshka/backup.pass
python3 /opt/trainer/deploy/snapshot.py restore snapshot.tar.gz /opt/trainer-restore-check
```

В снимок входят база, настройки и файлы, а не только SQLite. После обновления один раз выполните `backup.sh` и проверьте восстановление в пустой каталог. Храните пароль шифрования отдельно от сервера. Контрольные суммы выявляют повреждение снимка; они не заменяют защиту пароля и доверие к месту хранения.

## 6. Ограничения ресурсов

Новый HTTP-сервер ограничивает одновременно выполняющиеся запросы; для SSE и «Вместе» используется отдельный резерв. При перегрузке новый запрос получает 503 с повтором через две секунды, а не создаёт бесконечное число потоков. Значения `EGE_HTTP_WORKERS` и `EGE_STREAM_WORKERS` задаются в окружении службы. Шаблон systemd также ограничивает задачи процесса, закрывает повышение привилегий и устанавливает закрытые права новых файлов. После обновления шаблона нужны `systemctl daemon-reload` и перезапуск службы; обычное обновление исходников само шаблон не устанавливает. Значения памяти и CPU подбирайте по измерениям конкретного сервера.
В облаке хранятся последние 30 дней.
