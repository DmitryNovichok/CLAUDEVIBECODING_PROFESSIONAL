# Как выложить тренажёр на сервер с доменом

Итог: ученики открывают `https://ваш-домен/`, вводят код приглашения и ФИО, а вы смотрите журнал на `https://ваш-домен/admin`. Компьютер при этом можно выключать.

## Что понадобится

- **VPS с Ubuntu 22.04 или 24.04.** Хватит 1–2 ГБ памяти. Диска нужно столько, сколько весит папка `trainer` после шага 1 (картинки и файлы к заданиям) плюс запас. Подойдёт любой хостинг с VPS.
- **Домен или поддомен**, например `ege.ваш-сайт.ru`. У регистратора добавьте A-запись: домен → IP-адрес VPS.
  **Своего домена нет?** Подойдёт бесплатный адрес вида `195-19-209-50.sslip.io` (IP сервера через дефисы): он сам указывает на ваш сервер, и Caddy получит для него HTTPS-сертификат. Ничего регистрировать не нужно.
- **Открытые порты 22, 80 и 443.** У многих облаков есть свой брандмауэр («группы безопасности», «firewall») в панели — разрешите там входящие на эти порты.
- **Для загрузки файлов с Windows** удобнее всего WinSCP, для команд — PuTTY или встроенный `ssh` в PowerShell.

## 1. Подготовить папку на своём компьютере

```
cd Biblio\trainer
python build.py --standalone
```

Картинки и файлы к заданиям скопируются в `trainer\media`, и папка `trainer` станет самодостаточной: банки рядом ей больше не нужны.

Если ученики уже занимались, переносите данные из проверенной резервной копии (см. раздел ниже), включая приватные настройки. Файл работающей базы отдельно не копируйте: последние записи могут находиться в WAL. Для новой установки используйте чистую папку, без чужих серверных данных.

## 2. Загрузить на сервер

Скопируйте папку `trainer` целиком в `/opt/trainer` на сервере (в WinSCP — перетащить папку). Папку `.git` копировать не нужно. Архивы `*.zip` и `*.rar` в `media` **нужны**: это файлы к заданиям ФИПИ (3, 9, 17, 18, 22, 24, 26, 27), без них ученик получит «Файл недоступен на сайте».

Тысячи мелких файлов быстрее загрузить одним архивом. Из PowerShell (в папке `Biblio`):

```
tar -czf trainer.tgz --exclude=.git trainer
scp trainer.tgz root@IP_СЕРВЕРА:/opt/
ssh root@IP_СЕРВЕРА "cd /opt && tar -xzf trainer.tgz && rm trainer.tgz"
```

Проверьте размер `trainer` перед загрузкой (Свойства папки): на маленьком сервере диска может не хватить.

## 3. Настроить сервер

Подключитесь по ssh (`ssh root@IP_СЕРВЕРА`) и выполните по очереди:

```
# Python и отдельный пользователь для тренажёра
apt update && apt install -y python3
useradd -r -s /usr/sbin/nologin trainer
chown -R trainer:trainer /opt/trainer

# пароль учителя и код приглашения
sudo -u trainer python3 /opt/trainer/server.py --password ВАШ_ПАРОЛЬ
sudo -u trainer python3 /opt/trainer/server.py --invite ВАШ_КОД_ПРИГЛАШЕНИЯ

# запуск тренажёра как службы (сам поднимется после перезагрузки)
cp /opt/trainer/deploy/ege-trainer.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now ege-trainer
systemctl status ege-trainer --no-pager
```

Живые обновления (дуэли, турниры, подборки приходят сами) держат одно долгое соединение `/api/live` на браузер. Поэтому в службе стоит `LimitNOFILE=8192`. Caddy такие соединения пропускает сам, настраивать ничего не нужно. Если соединение не держится, сайт сам вернётся к обычному опросу сервера.

## 4. HTTPS и домен (Caddy)

Caddy принимает запросы на домен, сам получает сертификат Let's Encrypt и передаёт запросы тренажёру. Установка (официальные команды с caddyserver.com):

```
apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | tee /etc/apt/sources.list.d/caddy-stable.list
chmod o+r /usr/share/keyrings/caddy-stable-archive-keyring.gpg
chmod o+r /etc/apt/sources.list.d/caddy-stable.list
apt update && apt install -y caddy
```

Настройка:

```
cp /opt/trainer/deploy/Caddyfile /etc/caddy/Caddyfile
nano /etc/caddy/Caddyfile        # замените trainer.example.ru на свой домен, сохраните: Ctrl+O, Enter, Ctrl+X
systemctl reload caddy
```

Если на сервере включён брандмауэр, откройте порты 80 и 443: `ufw allow 80,443/tcp`. Порт 8000 открывать не нужно, тренажёр слушает только внутри сервера.

Через минуту откройте `https://ваш-домен/`, должно появиться окно входа. Панель учителя: `https://ваш-домен/admin`.

## Обновление

- **Задания.** На своём компьютере `python openfipi_parser.py` (по желанию), затем `python build.py --standalone`. Загрузите на сервер `trainer/data/bank.js` и новые файлы из `trainer/media` (в WinSCP удобна «Синхронизация»). Перезапуск не нужен, сервер подхватит новый банк сам.
- **Сайт** (`app.js`, `style.css`, `index.html`, `admin.*`, `changelog.js`): загрузить и обновить страницу.
- **`server.py`:** загрузить и выполнить `systemctl restart ege-trainer`.

После загрузки выполните `chown -R trainer:trainer /opt/trainer`.

## Резервная копия и логи

- Ученики и журнал хранятся в SQLite с WAL. Скачивайте проверенные архивы из `/opt/trainer-backups`, а не файл работающей базы.
- Что делает сервер: `journalctl -u ege-trainer -f` (выход: Ctrl+C).

## Безопасность

- **Ответы.** Ответы проверяет сервер, в странице их нет.
- **Вход.** Без кода приглашения задания не отдаются.
- **Перебор.** После 10 неверных паролей учителя или 30 неверных кодов приглашения с одного адреса за 15 минут сервер отвечает «Подождите» до конца этих 15 минут. За Caddy адрес ученика берётся из заголовка `X-Forwarded-For`, поэтому блокируется только тот, кто ошибается.
- **Cookie.** За HTTPS (Caddy передаёт `X-Forwarded-Proto: https`) cookie входа помечаются как `Secure`.
- **Файлы.** Сервер отдаёт только файлы сайта, `vendor/`, `media/` и картинки/файлы заданий из банков. Пути с `..` отклоняются, база `server_data/` и `data/bank.js` с ответами наружу не отдаются.
- **Смена пароля** в панели завершает все остальные сессии учителя.
- **Пароль учителя.** Пароль учителя не должен совпадать с кодом приглашения. Код можно менять в панели, когда он «ушёл» за пределы класса.

## Резервные копии

Скрипт `deploy/backup.sh` раз в сутки создаёт полный снимок `/opt/trainer-backups/trainer-ГГГГ-ММ-ДД-ЧЧММСС-PID.tar.gz` и хранит последние 14 снимков. Включить (один раз, под root):

```
sh /opt/trainer/deploy/install-backup.sh
```

Копия снимается в 09:50 по часовому поясу сервера (проверьте `timedatectl`). Если настроено скачивание на компьютер учителя, замените в нём маску `trainer-*.db.gz` на `trainer-*.tar.gz`. Последняя команда сразу делает первую копию. Настройте также отправку вне сервера (`deploy/RELIABILITY.md`). Старые копии только базы автоматически не удаляются.

Снимок содержит SQLite с WAL-транзакциями, весь `server_data` (включая частные настройки, изображения поддержки и файлы занятий «Вместе»), `media`, `data`, материалы курсов и найденные внешние `*_bank`. `snapshot.json` хранит размеры и SHA-256 всех файлов. Если файлы меняются во время копирования или ссылка из базы ведёт на отсутствующее вложение, копия завершается ошибкой: повторите её после окончания занятия. Незавершённые изменения «Вместе» в памяти попадут после штатного сохранения в базу.

Если служба использует `EGE_PRIVATE_CONFIG` вне `server_data`, передайте этот же путь окружением заданию резервного копирования. Отдельно сохраните конфигурацию Caddy/systemd, переменные окружения службы и пароль шифрования внешних копий. Они не находятся в каталоге приложения и автоматически в снимок не входят.

## Безопасное обновление и восстановление

Никогда не копируйте `server_data`, CSV-журналы и резервные копии из архива исходников на сервер.
Исходники обновляются через `rsync --exclude=server_data/ --exclude=.git/`, без `--delete`.
Перед обновлением запускайте `sh /opt/trainer/deploy/backup.sh`. Скрипт читает SQLite вместе с WAL,
проверяет целостность копии и только после успеха заменяет архив. При ошибке cron оставляет сообщение
в `/var/log/ege-backup.log`. Расписание использует часовой пояс сервера, проверьте `timedatectl`.

Проверка восстановления без изменения работающего сайта:

```
python3 /opt/trainer/deploy/snapshot.py restore /opt/trainer-backups/trainer-ВЫБРАННЫЙ.tar.gz /opt/trainer-restore-check
```

Каталог назначения должен быть новым или пустым. Скрипт отклоняет подменённые хеши, лишние файлы, ссылки и выход за каталог, проверяет SQLite. Протестируйте эту копию с соответствующей версией исходников на другом порту. Для внешних банков укажите `--banks /opt/trainer-restore-check/banks`. Для реального восстановления остановите службу, сохраните текущие данные отдельно, перенесите проверенный `server_data`, материалы и банки, выставьте владельца `trainer:trainer`, задайте фактический путь банков и запустите службу. Не смешивайте новую базу со старыми WAL/SHM.
Храните копии также вне сервера. Наличие cron и успешное восстановление проверяет администратор сервера.

## После публикации базы в Git

1. Остановите службу и сделайте защищённую резервную копию.
2. После установки новых исходников выполните `sudo -u trainer python3 /opt/trainer/server.py --revoke-access`.
   Команда отзывает сессии учеников и учителей, прежние токены и коды приглашений, меняет пароль доступа
   к курсу на неизвестный случайный. Учебные результаты и экономика не удаляются.
3. Смените пароли учителей и учеников: отзыв токенов НЕ делает старые пароли безопасными.
   Новый пароль курса и новые приглашения задайте через панель учителя. Пароли не публикуйте в Git.
4. Очистите историю Git по `deploy/PURGE_HISTORY.md`. Это отдельная операция, а не обычный коммит.
5. Перезапустите службу: прежние WebSocket-соединения также должны закрыться.


## Обязательная миграция приватных настроек перед первым обновлением до 2.21.1

В публичном коде больше нет таблицы индивидуальных наград и встроенных кодов.
До замены `server.py` запустите скрипт ИЗ НОВОГО распакованного архива:

```sh
sudo -u trainer python3 /tmp/НОВЫЙ_АРХИВ/deploy/preserve_private.py /opt/trainer/server.py /opt/trainer/server_data/private_config.json
```

Он переносит прежние значения без вывода на экран. Новая версия читает файл с правами 600,
а при его отсутствии не запускается, чтобы не изменить экономику молча. При повторном обновлении
существующие значения сохраняются. Таблицу и коды в Git не добавлять. Полный снимок `.tar.gz` содержит приватные настройки в `server_data/private_config.json`. У старых снимков только базы `.db.gz` настройки лежали рядом в `.private.json`: при восстановлении старого формата нужны оба файла.


## Почта: еженедельные отчёты учителям и заявки на продление (с 2.23.0)

Для писем нужны SMTP и корректный `SITE_URL`. При отсутствии этих настроек письма не уходят. Подтверждение почты нового учителя и уже включённый вход по почтовому коду автоматически не отключаются из-за сбоя почты. Недельный отчёт доступен и в панели: «Настройки» → «Посмотреть отчёт сейчас».
Чтобы письма уходили, добавьте в `/opt/trainer/server_data/private_config.json` (права 600, в Git не класть) ключи SMTP —
например, для Яндекс 360 нужен пароль приложения:

```json
"SMTP_HOST": "smtp.yandex.ru",
"SMTP_PORT": 465,
"SMTP_USER": "report@ваш-домен.ru",
"SMTP_PASS": "пароль-приложения",
"SMTP_FROM": "Egeshka <report@ваш-домен.ru>",
"SITE_URL": "https://egeshka.online"
```

Порт 465 — SSL, любой другой — STARTTLS. Те же значения можно задать переменными окружения `EGE_SMTP_HOST`, `EGE_SMTP_PORT`, …,
`EGE_SITE_URL`. После изменения — `systemctl restart ege-trainer`. Отчёты уходят по понедельникам с 8:00 по времени сервера,
каждому учителю не чаще раза в неделю. Свою почту главный учитель указывает в «Настройках» — на неё же приходят заявки на продление.

### Подтверждение почты (с 2.50.0)

Когда почта настроена (SMTP и `SITE_URL`), после регистрации уходит письмо со ссылкой `/confirm?t=…` (действует 3 дня).
Ученик занимается сразу, на главной — напоминание. Новый учитель, который зарегистрировался сам, получает рабочий доступ только после подтверждения почты и одобрения главным учителем. До выполнения обоих условий открыта страница статуса. Сбой SMTP не отменяет эти требования; на странице можно проверить состояние отправки и повторить её после восстановления почты. Старые учётные записи обрабатываются миграцией действующей версии, без массового сброса статусов.

Тарифы и контакты на главной странице (`/welcome`) задаёт главный учитель во вкладке «Учителя».
