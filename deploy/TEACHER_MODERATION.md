# Обязательные проверки учителя · 2.60.0

Обычный учитель получает доступ, когда одновременно подтверждена почта и главный учитель одобрил аккаунт. До этого `/admin` показывает только страницу проверки; API панели, режим «как ученик», совместные занятия и живые обновления закрыты. Гостевой вход больше не создаёт аккаунты. Старый гостевой аккаунт можно преобразовать в регистрацию, после которой обе проверки обязательны.

Главный учитель сохраняет доступ для модерации. Раздел «Учителя» показывает статус почты, решение и число ожидающих заявок. Доступны «Одобрить», «Отклонить» и «На пересмотр», последние два решения могут сопровождаться комментарием учителю. Создание аккаунта главным учителем считается одобрением; владелец всё равно должен указать и подтвердить свою почту.

## Перед обновлением

Используйте обычный приватный деплой с резервной копией базы. Для отправки писем должны быть настроены `EGE_SITE_URL=https://egeshka.online`, `EGE_SMTP_HOST`, `EGE_SMTP_PORT`, `EGE_SMTP_FROM`, а при необходимости — `EGE_SMTP_USER` и `EGE_SMTP_PASS`. Те же ключи без префикса `EGE_` поддерживаются в `private_config.json`. Секреты не кладите в репозиторий. Нужна проверка доставки на собственном тестовом адресе после развёртывания: наличие настроек не гарантирует доставку.

Если почта не настроена или временно не работает, регистрация сохраняется, но доступ остаётся закрыт. На странице проверки есть повторная отправка, исправление адреса, обновление статуса и выход. Подтверждение не может быть заменено решением модератора.

## Существующие аккаунты

Однократная миграция `teacher_gate_v1` переводит всех обычных учителей в `pending`. Главный учитель должен проверить их в разделе «Учителя». Сохраняются имя, пароль, приглашение, классы, ученики, результаты и оплаченный срок.

Раньше `email_ok=1` мог выставляться без письма. Миграция сохраняет подтверждение только при наличии использованного токена `et`, привязанного к текущему адресу аккаунта. Если такая запись уже очищена, потребуется подтвердить почту повторно. Следующий запуск миграцию не повторяет.

Пробные дни новых регистраций начинаются после второй проверки ровно один раз. Оплаченный срок и уже начавшийся пробный период старого аккаунта не перезапускаются. Повторное одобрение не добавляет дни. Изменение адреса почты закрывает доступ до нового подтверждения, сохраняя решение модерации.

## Проверка после развёртывания

1. Зарегистрировать собственный тестовый аккаунт: доступна только страница двух проверок.
2. Подтвердить почту: пока заявка не одобрена, панель и API закрыты.
3. Главным учителем одобрить заявку: панель открывается автоматически, пробный период начинается.
4. Вернуть заявку на пересмотр: новые запросы панели и действия в уже открытом совместном занятии блокируются.

Тесты `tests/test_teacher_moderation.py` проверяют оба порядка проверок, отсутствие SMTP, полномочия модератора, однократность пробного периода, смену почты, миграцию, выдачу страницы и кода, отзыв доступа к режиму ученика и совместному занятию. `tests/teacher-gate.test.cjs` проверяет состояния страницы, безопасный вывод комментария, исправление почты и завершение сессии.
