# Политика загрузки ресурсов

Сервер отправляет `Content-Security-Policy` с реальными ограничениями загрузки.
Генератор — `http_security.content_security_policy(headers, peer)`; он также
строит точный адрес WebSocket для текущего сайта. Отдельного заголовка
`Content-Security-Policy-Report-Only` для этой политики не требуется.

Это совместимая политика со списком разрешённых источников, **не nonce-based
strict CSP**: существующие встроенные скрипты, обработчик печати и стили пока
требуют `unsafe-inline`. Произвольный внешний JavaScript и JavaScript `eval` /
`Function` не разрешены. Политика не заменяет очистку HTML, проверку доступа или
изоляцию недоверенного кода.

## Разрешённые источники и причины

| Ресурс | Источники | Использование |
|---|---|---|
| Скрипты | Текущий сайт; `https://cdn.jsdelivr.net/pyodide/v0.28.3/full/` | Собственные сборки, локальный KaTeX, фиксированная версия Python. Остальные пакеты и версии на том же CDN не разрешены. |
| Fetch / XHR / SSE | Текущий сайт; тот же каталог Pyodide | API, живые обновления, загрузка файлов и Python runtime. |
| WebSocket | Только `ws[s]://<текущий хост[:порт]>/api/together/ws` | Совместное занятие. Нет разрешения `ws:` / `wss:` для всех хостов. |
| Worker | Текущий сайт и `blob:` | Python и Arduino создают Worker внутри отдельного iframe с непрозрачным origin. У Arduino дополнительная политика запрещает сеть, мост принимает только ограниченные события периферии. Само разрешение blob не является границей доступа. |
| Шрифты / стили | Текущий сайт; встроенные стили; `data:` для шрифтов | `vendor/fonts`, `vendor/katex`, `arduino/fonts`. Google Fonts не используются и не разрешены. |
| Изображения | Текущий сайт, `data:`, `blob:`, восемь перечисленных ниже HTTPS-хостов | Рисунки заданий, загрузки с компьютера, локальные картинки доски. |
| Рамки | Текущий сайт | Python использует opaque `srcdoc` с `sandbox="allow-scripts"` и собственной более узкой CSP. |
| Медиа | Текущий сайт, `blob:`, `data:` | Локальные медиаресурсы. |
| Объекты / плагины | Запрещены | `object-src 'none'`. |

Внешние изображения, обнаруженные в поставляемых банках: `ege.fipi.ru`,
`ucarecdn.com`, `www.vinformatika-edu.ru`, `i.ibb.co`, `sun9-79.userapi.com`,
`sun9-68.userapi.com`, `sun7-21.userapi.com`, `sun9-40.userapi.com`.
Ссылки на YouTube, Telegram, VK и источники задач открываются в новой вкладке;
допуск их JavaScript или iframe не нужен.

`wasm-unsafe-eval` разрешает необходимую компиляцию WebAssembly, но не JavaScript
`eval`. У Arduino удалена лишняя проверка `new Function(body)` в основной странице:
синтаксические ошибки по-прежнему разбирает Worker и передаёт обработчик `onerror`.
Старые обфусцированные обёртки могут пробовать `Function` внутри `try/catch`; их
предусмотренный переход к `window` сохраняется без разрешения `unsafe-eval`.

## Дополнение банка изображений

Предпочтительно хранить картинки нового банка на своём сервере. Если нужен новый
внешний источник, оператор может явно добавить **точный HTTPS origin** в переменную
окружения сервиса `EGE_CSP_IMAGE_ORIGINS` и перезапустить сервис, например:

```ini
[Service]
Environment="EGE_CSP_IMAGE_ORIGINS=https://images.example.org https://assets.example.org:8443"
```

Разрешены разделители пробел и запятая. Шаблоны, HTTP, пути, query, данные входа и
произвольные директивы не принимаются; неверная настройка останавливает запуск с
понятной ошибкой. Дополнение расширяет только `img-src`, никогда скрипты, API или
политику Python-frame. Оно не задаётся через ученический или учительский интерфейс.

`X-Forwarded-Host` / `X-Forwarded-Proto` учитываются только для запросов с loopback,
как в существующей конфигурации reverse proxy. Динамический хост проверяется перед
включением в CSP: значение заголовка не может добавить собственную директиву.

## Проверки и границы

- `tests/test_csp.py`: закрытый список источников, точные WebSocket origin/порт,
  попытки внедрения директив через заголовки, настройки изображений, инвентаризация
  реальных картинок из банков и совпадение версии Pyodide.
- `tests/browser/csp.spec.cjs`: настоящий браузер должен отклонить сторонние
  script/fetch/WebSocket и непроверенные пути CDN; при этом сохранить локальные
  HTTP/WS, WASM, Blob Worker, картинки и шрифты.
- `tests/browser/python-sandbox.spec.cjs` использует **эту же серверную CSP**, чтобы
  проверить Python, stdin, файлы, turtle и трассировку при наследовании политики.
- `arduino/source/tests/runtime.test.js`: запрет `Function` в странице не мешает
  показать синтаксическую ошибку учебного кода из Worker.

Полный браузерный прогон необходим в обычной среде Chromium/CI. Если текущая среда
не запускает sandbox браузера, прохождение Python/Node-проверок не считается
подтверждением браузерной совместимости; запрещённые механизмы запуска не обходятся.

Наличие `unsafe-inline` означает, что эта итерация не исключает исполнение любой
внедрённой встроенной программы. Разрешённые внешние источники изображений также
не делают CSP универсальной защитой от передачи данных. У opaque Python-frame
остаётся отдельное более строгое ограничение сети только каталогами runtime;
эта политика не ослабляет его и не добавляет доступ к API.

## Первичные спецификации

- [W3C Content Security Policy Level 3](https://www.w3.org/TR/CSP3/): source lists,
  WebAssembly, Worker и наследование политики `srcdoc` / `blob:`.
- [Pyodide 0.28.3: использование](https://pyodide.org/en/0.28.3/usage/index.html):
  путь фиксированной сборки runtime.
- [Pyodide: журнал изменений](https://pyodide.org/en/0.28.3/project/changelog.html):
  работа без JavaScript `unsafe-eval` с отдельным допуском WASM.
