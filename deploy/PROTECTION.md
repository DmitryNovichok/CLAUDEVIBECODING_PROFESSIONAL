# Обновление защиты Egeshka

Версия 2.59.1 продолжает изменения 2.58.0–2.59.0. Она не меняет пароли, сессии, результаты работ или базу учеников.

## Что проверяется

- Исходные модули, сервер, конфигурация и банки с ответами не публикуются как статические файлы.
- Файлы из `MIN_FILES` выдаются только из `min/`. Если сборка потеряна, сервер отвечает 404 вместо раскрытия исходника.
- Панель учителя, лабораторный worker и Arduino проверяют доступ перед выдачей. Закрытые файлы получают `private, no-store`, в том числе по URL с `?v=`. Условный запрос не возвращает старую закрытую копию после выхода.
- Служебные файлы, карты исходников и временные файлы баз не раздаются из каталогов медиа и библиотек.
- Исходники и лицензии Arduino, предоставляемые вместе с приложением, остаются доступны пользователю с доступом к Arduino.
- `tools/check_release.py` проверяет SHA-256 исходников и сжатых копий без установки Node на сервере. Это защита от неполной/устаревшей сборки, не цифровая подпись доверенного издателя.

Браузерный JavaScript всё равно можно сохранить. Минификация сокращает имена и удаляет комментарии, но не заменяет серверную проверку доступа. Уже скачанные посетителем файлы отозвать невозможно.

## Подготовка кода

```sh
python3 tools/build_app.py
python3 tools/minify.py
python3 tools/check_release.py
```

В коммит включаются читаемые исходники, изменённые файлы `min/` и `min/manifest.json`. В CI дополнительно пересобирается минифицированный код и сравнивается побайтово. Не публикуйте source maps и не помещайте токен GitHub в папку сайта.

## Первый переход с публичного скачивания на приватный репозиторий

Старый `update.sh` из 2.57.0 не умеет скачивать приватный репозиторий. Сначала получите из проверенного коммита два файла `deploy/update.sh` и `deploy/github_release.py` и положите их **в одну временную папку на сервере** (например, `/root/egeshka-update`). Рабочий код сайта на этом этапе не изменяется.

Создайте fine-grained токен GitHub только для этого репозитория с разрешением **Contents: Read-only**, затем в терминале сервера под root:

```sh
sh /root/egeshka-update/update.sh --set-token
sh /root/egeshka-update/update.sh ПОЛНЫЙ_SHA_ПРОВЕРЕННОГО_КОММИТА
```

Первый ввод скрыт, токен проверяется до сохранения, хранится с правами 600 в `/root/.egeshka-github-token` и не передаётся в аргументах процесса. Не присылайте его в чат. Если этот файл уже настроен, повторный ввод не нужен.

Обновление делает резервную копию базы, скачивает конкретный коммит, проверяет пути архива, сборку приложения и сжатые ресурсы. Только после проверки заменяет код и перезапускает `ege-trainer`. При провале проверки доступности возвращает прежний код. `server_data/` сохраняется, имеющиеся медиа не удаляются.

## Последующие обновления

```sh
sh /opt/trainer/deploy/update.sh ПОЛНЫЙ_SHA_ПРОВЕРЕННОГО_КОММИТА
curl -fsS https://egeshka.online/api/health
```

После первого применения защиты попросите пользователей обновить страницу с очисткой кэша (Ctrl+Shift+R или Cmd+Shift+R): прежние публичные URL могли уже сохраниться у них в браузере или промежуточном кэше.
