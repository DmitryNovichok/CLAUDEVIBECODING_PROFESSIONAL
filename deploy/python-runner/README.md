# Независимая проверка Python

Основной сайт не исполняет Python ученика. `buglab_verifier.py` передаёт только
код и выбранные сервером входные данные отдельному процессу через Unix-сокет.
Исполнитель работает под отдельным пользователем `ege-python` и запускает
**новый rootless Podman-контейнер для каждого теста**. Ответы-эталоны, сессии,
идентификаторы учеников, база сайта и почтовые секреты ему не передаются.

До запуска ученического файла доверенный entrypoint проверяет фактически
действующие ограничения. Если проверки не прошли, код не запускается. Клиент
проверяет владельца сокета, UID процесса, версию протокола, идентификатор запроса,
хеш программы с входами, число и форму результатов. Подмена браузерного `runs`
не участвует в этой проверке.

| Ограничение | Значение |
|---|---|
| Активные запросы | 2; остальные получают отказ «занято» |
| Программа / вход / число тестов | 32 КиБ UTF-8 / 16 КиБ / 12 |
| Контейнер | Непривилегированный UID 65534, без capabilities, no-new-privileges, seccomp |
| Сеть | Отдельное пространство сети, только loopback, без сети хоста |
| Файлы | Read-only образ и единственный read-only файл программы; временный `/tmp` 16 МиБ |
| Процессор / память / процессы | 1 CPU, CPU time 2/3 с, память 256 МиБ, swap 0, PIDs 32 |
| Время | 6 с на запуск, 8 с независимый таймер conmon, общий бюджет запроса 80 с |
| Вывод | stdout 20 000 байт, stderr 2 000 байт |
| Образ | Неизменяемый локальный `sha256:…`; при проверках `--pull=never` |

После таймаута или переполнения вывода остальные тесты не запускаются. Контейнер
удаляется по созданному сервером уникальному имени. Ошибка удаления блокирует
дальнейшие задания до вмешательства администратора. Служба не имеет резервного
запуска в CPython хоста, привилегированном контейнере или ослабленном профиле.
Контейнеры используют ядро хоста: обновление ОС, Podman и базового образа остаётся
обязанностью администратора. Для большего разделения можно выделить исполнителю
отдельную машину; текущий клиент рассчитан на локальный защищённый Unix-сокет.

## Установка

Нужен Linux с cgroup v2, работающим rootless Podman, seccomp, `newuidmap`,
`newgidmap`, systemd user manager и непересекающимися диапазонами subuid/subgid.
На Debian/Ubuntu обычно нужны пакеты `podman uidmap dbus-user-session`.
Совместимость конкретной версии Podman и настроек сервера устанавливается
командой `--probe` и приёмочными тестами ниже; здесь она не предполагается.

Выберите digest официального образа Python 3.12 slim из Docker Official Images.
Можно получить digest с помощью `skopeo inspect --format '{{.Digest}}'
docker://docker.io/library/python:3.12-slim-bookworm`, проверить его и сохранить
в журнале развёртывания. Установщик принимает **digest, а не изменяемый тег**:

```sh
sudo sh deploy/python-runner/install.sh docker.io/library/python@sha256:ПРОВЕРЕННЫЙ_DIGEST
```

Установщик создаёт отдельного пользователя и группу доступа к сокету, копирует
доверенные файлы в `/opt/ege-python-verifier`, собирает образ без сети из
загруженного digest и сохраняет итоговый image ID в `/etc/ege-python-verifier/image`.
Он проверяет изоляцию **до** старта службы. Если probe завершается ошибкой,
нельзя заменять параметры на `--privileged`, `--network=host`, отключать seccomp,
снимать лимиты или добавлять fallback. Нужно исправить окружение либо оставить
независимую проверку недоступной.

Служба — rootless user unit `ege-python-verifier.service`. Её broker использует
штатные `newuidmap/newgidmap`; ограничения непроверенного кода задаются внутри
контейнера и проверяются entrypoint. Сокет `/run/ege-python-verifier/runner.sock`
доступен группе `ege-verifier`; перезапустите `ege-trainer`, чтобы пользователь
`trainer` получил добавленную группу. Служба не слушает TCP-порт.

## Таймаут обратного прокси

Запрос `/api/lab/bugs/verify` может ожидать исполнителя до 100 секунд. В поставляемом
`deploy/Caddyfile` таймаут ответа upstream не задан: у Caddy по умолчанию он отсутствует
([официальная документация](https://caddyserver.com/docs/json/apps/http/servers/routes/handle/reverse_proxy/transport/http/response_header_timeout)).
Если рабочий прокси или внешний балансировщик задаёт более короткий лимит,
установите для этого маршрута ожидание ответа не меньше 120 секунд и проверьте
длинный запуск через настоящий домен. Не увеличивайте лимиты загрузки тела запроса
и не отключайте проверку Origin. Сам код ограничивается исполнителем независимо
от таймаута HTTP. Обрыв вкладки не означает отмены уже отправленной проверки;
её сохранённый результат виден после повторного открытия лаборатории.

## Обязательная приёмка на установленном исполнителе

Эти команды запускают именно отдельную изолированную среду; при недоступном
runtime проверка должна завершиться ошибкой, а не перейти к запуску на хосте.
Из корня установленного репозитория:

```sh
runner_uid=$(id -u ege-python)
runner_image=$(cat /etc/ege-python-verifier/image)
sudo -u ege-python env XDG_RUNTIME_DIR=/run/user/$runner_uid \
  /usr/bin/python3 /opt/ege-python-verifier/python_executor.py --probe
sudo -u ege-python env XDG_RUNTIME_DIR=/run/user/$runner_uid EGE_RUNNER_IMAGE=$runner_image \
  python3 -m unittest discover -s tests -p test_python_runner_container.py
sudo systemctl restart ege-trainer
```

Проверяется правильная и неправильная программа, отсутствие файлов/секретов
хоста, сети и записи в корневую ФС, таймаут, ограничение вывода и памяти,
отсутствие файлов предыдущего теста. Затем через сайт проверьте: независимый
успех выдаёт подтверждённый результат, подставленные `runs` не выдают награду,
остановленная служба возвращает недоступность без изменения прогресса.

**В рабочем окружении разработки Podman отсутствовал. Контейнерные приёмочные
тесты здесь не выполнялись.** Проверки протокола, лимитов supervisor и отказов
выполнены отдельно; пять тестов настоящего Unix-listener требуют CI, поскольку
окружение запрещает создание таких слушателей. Opt-in container tests без
`EGE_RUNNER_IMAGE` отмечаются как пропущенные, а при указанном образе неисправная
изоляция считается провалом теста.

## Подключение к сайту и восстановление

Вызов `buglab_verifier.verify(case, code)` получает `case` из серверного
`buglab.BY_ID`. Он возвращает `{ok, verified: true, provenance: "server_python",
tests, changed, par}`. `InvalidProgram` означает HTTP 400, `VerifierBusy` —
429 с Retry-After, `VerifierUnavailable` — 503. Исключение означает отсутствие
вердикта: не сохраняйте ошибочную попытку и не выдавайте награду.

Авторизация и лимиты проверяются до вызова; DB-транзакция во время работы
контейнеров не удерживается. Перед сохранением снова проверяются сессия и доступ.
Старые самопроверки остаются неподтверждёнными. Награда опирается только на
независимый успех; последующая самопроверка не должна переписывать доказательство.

Для восстановления сохраните image ID, точный OCI-образ либо digest базового
образа с Containerfile/entrypoint, root-owned файлы `/opt/ege-python-verifier`,
`/etc/ege-python-verifier/image`, user unit, tmpfiles-конфигурацию, пользователя и
диапазоны subuid/subgid. Временные файлы заданий не сохраняются. После восстановления
обязательно повторите probe и приёмочные тесты; проверка копии основной БД сама
по себе не подтверждает работоспособность исполнителя.
