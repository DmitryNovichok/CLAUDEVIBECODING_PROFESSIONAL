# Карта типов задач и навыков

Карта различает три вещи:

1. **Найден материал:** есть конкретный слайд, уровень Python, подобранный пример или ограниченная учебная модель.
2. **Целостность ссылок:** позиция и заголовок совпадают с исходником, указанные в выбранном материале входные файлы присутствуют. Изменение заголовка, удаление слайда или отсутствующий файл не сохраняют прежний статус исправной ссылки.
3. **Предметная полнота и корректность:** независимая проверка, что материал полноценно обучает навыку, а все ответы соответствуют условиям. Эта проверка **не выполнена**, и автоматические тесты не превращают её в выполненную.

`learning-skill-map.json` связывает каждый ключ текущей таксономии `clusters.RULES` с фактическими слайдами/уровнями/примерами. Индексы в карте начинаются с нуля, в интерфейсе — с единицы. Наличие записи без источников означает явный пробел в карте, а не доказательство отсутствия материала во всех возможных источниках. Заголовки и файлы проверяются при построении отчёта; полные условия, ответы, код, имена и URL файлов не выдаются публично.

При проверке дерева 16.11.2026 карта содержит 86 типов из классификатора и 8 дополнительных навыков: отдельные стратегии №20–21, пять приёмов строковых задач №24 и различение признака/метрики №27. Из 94 записей (включая архив) у 88 найдены ссылки на материалы, у 6 явной связи нет. Это **не 88 подтверждённых навыков**. Дополнительные записи «Другие формулировки» сохраняют видимость неклассифицированных заданий.

Сейчас явно отмечены пробелы: площадь и длина следа Черепахи; подсчёт символов на ленте; восстановление IP-адреса из фрагментов; графовые маршруты внутри действующего №23; исторические задачи №27 на последовательности. Материалы по графам находятся отдельно в архиве. Есть и частичные связи: теория без решённого примера, упражнение на пятёрки вместо всех длинных наборов, вложение коробок вместо всех вариантов сборки. Эти ограничения показываются рядом с конкретным типом.

## Счётчики и стоимость запроса

Базовый `GET /api/course/coverage` остаётся краткой картой номеров/форматов. Подробный `?skills=1` запрашивается только после раскрытия блока навыков. Статические JSON кешируются по пути, времени изменения и размеру; обновление файла инвалидирует запись. Счётчики используют уже аннотированный серверный банк: повторная классификация не запускается для заданий с `c`. Для неаннотированных данных используется тот же эвристический классификатор, поэтому результат не считается экспертной разметкой.

Части общего задания №19–21 считаются у своих номеров, как в базовой карте. Для отдельного навыка без собственного классификатора показывается счётчик родительского типа или раздела с явным указанием, что это не количество упражнений именно на этот навык. Эти строки нельзя суммировать. Python `level_inventory` — весь связанный уровень; `selected_examples` — конкретно подобранные примеры. Ни один вариант не означает проверенную полноту навыка.

## Повторная проверка

```bash
python3 tools/audit_learning_skills.py
python3 -m unittest discover -s tests -p 'test_learning_skills.py'
```

Первый инструмент не читает базу учеников и не изменяет файлы. Код возврата 1 означает изменённую/пропавшую ссылку или недоступный входной файл; явные пробелы материала сами по себе не ломают выпуск. Код 0 подтверждает только целостность указанных ссылок. Проверки программ уроков отдельно подтверждают совпадение вывода с записанным ответом; это внутренняя согласованность, а не независимая математическая проверка.

## Редакционные исправления

Внутри Python-уроков сохранены все ID, задания, уровни и ключи прогресса. Исправлены устаревшие титульные слайды: IP-адреса — №13, исполнитель — №23, как в ранее проверенной утверждённой карте ФИПИ-2027. Исправлены и исходники генератора, чтобы ошибка не вернулась при сборке.

В уроке №27 заголовок «Формат проекта-2027» заменён на «Учебный пример: группы по признаку». Наличие конкретного примера с энергией частиц не означает, что вся официальная тема ограничена таким сюжетом. Код, данные и ответы примера сохранены; источник генерации и JSON согласованы.

Следующая предметная проверка должна разбирать условия, решения, достаточность примеров и граничные случаи по каждому навыку. Её результаты следует хранить с областью проверки и версией исходников. До такой работы `semantic_verified` и `answers_verified` остаются ложными.
