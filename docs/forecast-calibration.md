# Проверка прогноза по настоящим пробникам

Сначала собираются прогнозы **до начала пробника**, затем добавляются фактические результаты. Инструмент не обновляет модель сайта, не создаёт учеников и не подставляет вымышленные оценки. Пока собственная выборка не собрана, нельзя объявлять прогноз откалиброванным.

## Подготовить и проверить импорт

```sh
python tools/calibrate_forecast.py template --output /private/forecast-cohort.csv
python tools/calibrate_forecast.py validate --input /private/forecast-cohort.csv
python tools/calibrate_forecast.py evaluate --input /private/forecast-cohort.csv --output /private/forecast-report.json
python tools/calibrate_forecast.py evaluate --input /private/forecast-cohort.csv --format markdown --output /private/forecast-report.md
```

Каталог `/private` — пример закрытого каталога оператора вне раздаваемых файлов сайта. Файлы надо хранить с ограниченными правами. Существующие файлы инструмент не перезаписывает. Шаблон содержит только заголовки, без примеров результатов.

| Поле | Значение |
|---|---|
| `student_key` | Постоянный случайный код ученика. Одинаковый во всех его пробниках; без ФИО, почты, логина и токенов. Таблицу соответствия хранить отдельно. |
| `exam_key` | Код конкретного пробника; одна строка на ученика и пробник. |
| `predicted_at` | Момент фиксации прогноза, строго до начала пробника. |
| `exam_started_at`, `exam_finished_at` | Фактическое начало и окончание. Даты ISO 8601 с часовым поясом. |
| `prediction` | Прогноз 0–100, зафиксированный заранее. Не пересчитывать после появления ответов пробника. |
| `actual` | Реальный тестовый балл 0–100, целое число. Первичные баллы сюда не подходят. |
| `independent_answers_30d` | Число подходящих самостоятельных ответов за 30 дней **на момент фиксации прогноза**. |
| `covered_numbers_30d` | Число номеров с такими ответами, от 0 до 27, также на момент прогноза. |
| `model_version` | Версия модели, создавшей прогноз. Разные версии оцениваются отдельно. |
| `source` | `supervised_mock`, `external_mock`, `platform_mock`; `synthetic` допустим только для отдельной проверки самого инструмента. |

Старую дневную историю балла нельзя автоматически считать полноценной записью для этой таблицы: у неё может не быть точного времени, версии модели и исторического покрытия. Не дополняйте эти поля текущими значениями задним числом. Порядок сбора и состав группы фиксируют заранее; отсутствие реальных данных является незавершённым измерением, а не программной ошибкой.

Импорт отвергает повтор строки пробника, прогноз после начала экзамена, прогноз старше 30 дней, невозможные числа, лишние столбцы и смешивание настоящих и учебных данных. Он не может доказать, что экзамен был проведён независимо: происхождение оценок и отсутствие помощи проверяет организатор.

## Как разделяются данные

Неизменяемая функция от кода ученика относит его в `train` (около 60%), `validation` (около 20%) или `holdout` (около 20%). Все пробники одного ученика остаются в одной группе. Не переименовывайте коды и не перебирайте выборки ради улучшения метрик.

Каждый ученик имеет одинаковый суммарный вес внутри отчётной группы, поэтому десятки пробников одного человека не перевешивают остальных. Показаны число учеников и экзаменов, MAE, RMSE, смещение «прогноз минус факт» и доля ошибок не больше пяти баллов. Группы подготовленности определяются **исходным прогнозом**, а не фактическим результатом.

Минимум для пробного подбора поправки: 30 разных учеников `train`, 15 `validation` и 15 `holdout`. Это технический порог эксперимента, а не гарантия статистической достаточности. На `train` рассчитывается только среднее смещение, на `validation` оно выбирается лишь при улучшении MAE минимум на 0,5 балла. Затем один раз измеряется результат выбранного варианта на `holdout`. Сайт автоматически эту поправку не применяет.

После просмотра `holdout` его нельзя снова использовать как нетронутую проверку для очередного подбора. Следующее изменение подтверждают на новой будущей группе. Доверительные интервалы и обещания экзаменационного результата этот инструмент не выдаёт.

Показатель свежего покрытия отдельно считает, у какой доли пробников прогноз опирался на все 27 номеров за 30 дней. Неполное покрытие не превращается в утверждение, что ученик не знает остальные темы.

## Проверка исправления ошибок

`learning_quality.followup_metrics` оценивает первое следующее новое задание того же номера и классифицированного типа. Подсказки, «Вместе», уже встречавшиеся задания, открытие ответа и незавершённые попытки исключаются. Успех означает правильный ответ с первой попытки; ответ со второй попытки не скрывает повторную ошибку.

Если похожего задания ещё не было или тип неизвестен, показатель остаётся без оценки. Правильный следующий ответ — наблюдаемый признак переноса навыка, а не доказательство исчезновения конкретной причины или эффекта платформы. Общий объём банка и число слайдов в эту метрику не входят.
