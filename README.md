# Egeshka — тренажёр ЕГЭ по информатике

Сайт с банком заданий. Слева — номера 1–27 с количеством заданий, по центру — тренажёр, который подбирает задания под ученика.

## Установка

1. Положите папку `trainer` в `Biblio`, рядом с `ege_bank` и `kompege_bank`:

   ```
   Biblio/
     ege_bank/
     kompege_bank/
     trainer/      ← сюда
   ```

2. Откройте терминал в папке `trainer` и выполните:

   ```
   python build.py
   ```

   Скрипт обойдёт `ege_bank/tasks` и `kompege_bank/tasks`, соберёт задания в `data/bank.js` и напишет отчёт в `data/report.txt`. Нужен только Python 3.8+, ничего устанавливать не надо.

3. Откройте `index.html` двойным кликом.

После обновления банка заданий снова запустите `python build.py`.

### Если вместо картинки «Рисунок не загрузился»

Картинки и файлы к заданиям лежат не в тренажёре, а в папках банков (`Biblio/ege_bank`, `kompege_bank`, `openfipi_bank`). В репозиторий они не входят. Поэтому:

- **Сервер (`python server.py`) ищет банки сам:** рядом с тренажёром, на несколько папок выше (и в `Biblio` там), а также по путям, которые сборщик записал в `data/report.txt` при прошлой сборке. Поэтому тренажёр, скачанный с GitHub в «Загрузки», обычно всё равно находит банки. При запуске сервер пишет, где нашёл каждый банк.
- **Если не нашёл — укажите папку один раз:** `python server.py --banks "C:\Users\…\Biblio"` (папка, внутри которой `ege_bank`, `kompege_bank`…). Путь запоминается.
- **При открытии `index.html` двойным кликом** (без сервера) банки должны лежать строго рядом с папкой тренажёра — браузер сам их не ищет. Запускайте через сервер.
- **Для сервера в интернете или передачи ученикам** соберите банк с `python build.py --standalone`. Картинки скопируются в `trainer/media`, и эту папку нужно выложить вместе с остальными файлами.
- `build.py` без `--root` тоже ищет банки рядом с тренажёром и выше по папкам.

Сервер при запуске сам пишет, каких папок не хватает, а в панели учителя появляется предупреждение. Если у картинки была ссылка на сайт источника, тренажёр, не найдя файла, загрузит её оттуда (для этого банк нужно один раз пересобрать `build.py`). Иначе вместо картинки будет ссылка на задание на сайте источника.

### Если файлы к заданиям не скачиваются

При открытии через двойной клик некоторые браузеры открывают .txt во вкладке, а не скачивают. Запустите простой сервер в папке `Biblio`:

```
python -m http.server 8000
```

и откройте http://localhost:8000/trainer/

### Выложить на хостинг или отдать ученикам

```
python build.py --standalone
```

Картинки и файлы к заданиям скопируются в `trainer/media`. После этого папку `trainer` можно выложить на любой статический хостинг (GitHub Pages, Netlify, свой сервер) или отправить архивом — банки рядом больше не нужны.

### Другие параметры

```
python build.py --root "D:/Biblio"                     # если trainer лежит не в Biblio
python build.py --bank ege_bank                        # только один банк
python build.py --bank ege_bank --bank kompege_bank    # явно перечислить банки
```

Папки `out`, `raw`, `ege_bank_math_base` и `ege_bank_math_prof` не используются.

## Сервер: вход учеников и журнал для учителя

Без сервера тренажёр работает сам по себе: прогресс хранится в браузере, учитель ничего не видит. Чтобы ученики входили под своими ФИО, а вам приходил журнал, запустите сервер:

```
python server.py
```

Сервер напечатает адреса:

```
На этом компьютере:     http://localhost:8000/
Для учеников в сети:    http://192.168.1.23:8000/
Панель учителя:         http://localhost:8000/admin
Код приглашения:        16082001
Пароль учителя: …   (только при первом запуске — сохраните его)
```

**Ученик** при первом заходе регистрируется (вкладка «Регистрация»): код приглашения, фамилия с именем и пароль. Потом входит по ФИО и паролю с любого устройства, прогресс тот же. Без входа задания не загружаются.

Вход — свой на каждом устройстве (таблица `student_sessions`): «Выйти» закрывает его на сервере, смена пароля — на остальных
устройствах, сброс пароля учителем и «Выйти везде» в карточке ученика — на всех. Обычный вход живёт `STUDENT_COOKIE_DAYS`
(30) дней с последнего захода. **Компьютеры в классе:** если с адреса за `SHARED_DAYS` (30) дней решали или входили
`SHARED_MIN` (3) и больше разных учеников, это школьная сеть (`shared_ip`): вход там временный — cookie до закрытия
браузера, не дольше конца дня и `SHARED_IDLE` (3 часа) без действий; поле пароля — текст со звёздочками
(`-webkit-text-security`), поэтому браузер пароль не сохраняет и сохранённый раньше не подставляет (в Firefox и на телефонах —
`autocomplete="new-password"`); ФИО прошлого ученика не подставляется; 40 минут без действий (кроме варианта ЕГЭ) — выход
сам. Учитель во вкладке «Ученики» нажимает «Выйти всем на компьютерах класса» — входы его учеников с того же адреса, что у
него сейчас, закрываются (`/api/admin/logout-here`), открытые страницы сразу показывают окно входа. Ученик видит свои входы
и может выйти на всех других устройствах в «Пароль и входы». Прежний общий токен (`students.token`) вне школьной сети ещё
`LEGACY_DAYS` (30) дней сам становится входом устройства, в школьной сети не действует.

- **Пароль** меняется в левой панели («Пароль»). После смены вход на других устройствах сбрасывается. «Выйти» нужна, когда за одним компьютером занимаются по очереди.
- **Забыл пароль** — учитель нажимает «Сбросить пароль» в карточке ученика. Ученик снова проходит «Регистрацию» с тем же ФИО и кодом приглашения и придумывает новый пароль. Журнал и прогресс сохраняются.
- **Ученики, которые входили до появления паролей,** при следующем заходе задают пароль (с кодом приглашения). Их журнал сохраняется.
- **Подбор пароля** ограничен: после 10 неверных паролей к одному ученику (или 30 с одного адреса) вход на 15 минут закрыт. Зарегистрироваться под уже занятым ФИО нельзя.

**Панель учителя** (`/admin`, вход по паролю):

- **Ученики.** Кто когда заходил, сколько решено сегодня и за неделю, доля верных с первой попытки, число ошибок, сколько раз открыл ответ, балл за последний вариант ЕГЭ, прогноз балла. Значок **⚠** — подозрительно много открытых ответов (упирался в лимит, больше 30 за неделю или ответ открыт в половине заданий): так ответы выкачивают, а не решают.
- **Карточка ученика:**
  - сводка: решено, точность, прогноз, время, сколько ответов открыто (и сколько раз ученик упёрся в лимит), варианты ЕГЭ с баллами;
  - с какого адреса заходил и кто ещё входил с того же адреса (много новых ФИО с одного адреса — повод проверить);
  - номера 1–27 с точностью и числом ошибок;
  - разбивка по дням («24 задания: 18 верно, 4 ошибки — в №5, №14, №24»);
  - журнал: что задано, что ответил ученик (с обеих попыток), правильный ответ, итог, время на задание. Фильтры «Ошибки» и «Верно» и по номеру. Клик по заданию открывает его условие с ответом.
- **Несколько учителей.** Главный учитель (логин `admin`, пароль прежний, можно входить и с пустым логином) на вкладке **«Учителя»** добавляет других учителей: имя, логин, пароль и код приглашения (если оставить пустым, код придумается сам). У каждого учителя свой код приглашения: ученик, зарегистрировавшийся по нему, попадает к этому учителю. Учитель видит только своих учеников, свои классы, подборки, ленту и выгрузку; код приглашения, пароль, переключатель авторских заданий и решения к заданиям у каждого свои. Главный видит всех (столбец «Учитель»), может передать ученика другому учителю в его карточке, изменить учителю пароль или код и удалить учителя — его ученики, классы и подборки перейдут главному. ФИО ученика уникально на весь сайт: при совпадении пусть добавит отчество.
- **Классы.** На вкладке «Ученики» видны только новые ученики без класса. Отметьте их галочками и нажмите «Перенести в класс». На вкладке «Классы» можно создать, переименовать и удалить класс, а также посмотреть учеников класса. При удалении класса ученики возвращаются в «Новые», результаты сохраняются. Переключатель «Все ученики» над таблицей показывает всех сразу.
- **Подборки заданий.** В классе нажмите «Новая подборка», дайте название и срок, добавьте случайные задания нужного номера или конкретные по номеру КомпЕГЭ / коду ФИПИ, расставьте порядок кнопкой ↑. Ученики класса видят подборку в карточке «Задания от учителя» и решают задания по порядку. У каждой подборки виден прогресс каждого ученика: сколько решено, кто ещё не начинал. В подборке засчитываются решения, сделанные после её выдачи.
- **Авторские задания** определяются по источнику и по подписи в начале условия: «(Д. Бахтиев) В файле…», «(PRO100 ЕГЭ)…». Так подписано около 2500 заданий КомпЕГЭ.
- **Уход со вкладки.** Если ученик уходит со страницы дольше чем на 2 секунды, пока открыто задание или вариант, это записывается. В таблице учеников есть столбец «Уходил» за 7 дней, в журнале — «Уход» у каждой попытки, в карточке ученика — сколько раз и сколько всего времени, отдельно во время варианта и попытки нажать клавиши снимка экрана. Учтите: в ЕГЭ по информатике многие задания решают в Excel или Python, поэтому уход на 24–27 номерах обычно честный. Подозрительны уходы на коротких заданиях и во время варианта.
- **Уровни учеников** видны в таблице («Ур.») и в карточке ученика.
- **Лента.** Все ответы всех учеников, обновляется сама.
- **Выгрузка CSV** в Excel: по ученику или по всем сразу.
- **Настройки:** код приглашения, пароль, адрес для учеников, переключатель «Авторские задания» — давать ли ученикам в подборках и вариантах задания авторов (Джобс, /dev/inf, Danov, Статград и др.) или только задания с экзаменов и из ФИПИ.
- Переименовать ученика (если ввести уже существующие ФИО, журналы объединятся) или удалить.

**Как это устроено:**

- **Защита.** После 10 неверных паролей учителя или 30 неверных кодов с одного адреса — пауза до 15 минут. Текст заданий из банков очищается от скриптов перед показом. В выгрузке CSV ответы вида `=…` не превращаются в формулы Excel.
- **Проверка ответов.** Ответы проверяет сервер: в странице их нет, подсмотреть в коде нельзя.
- **Итоги в журнале.** Попытка записывается с одним из итогов: «верно», «со 2-й попытки», «неверно», «показал ответ», «сдался, ответ скрыт» или «ушёл после ошибки» (ученик ответил неверно и переключился на другое задание или перезагрузил страницу). Ответы варианта ЕГЭ помечены «вариант». У №26 и 27 отмечается «½», если верна половина ответа.
- **Попытки считает сервер.** На задание две попытки; страница не может их подделать или обнулить перезагрузкой.
- **Показ ответа.** Открыть ответ можно не раньше чем через 40 секунд после показа задания (у №24–27 — через 90): сначала нужно попробовать решить. И не больше 12 ответов в час на ученика и 150 на один адрес — на случай выдуманных ФИО (класс в школе обычно сидит за одним адресом, поэтому лимит на адрес больше). Если рано или лимит исчерпан, ответ скрыт, а под заданием идёт обратный отсчёт и кнопка «Показать ответ». Числа — в начале `server.py` (`THINK_SEC_*`, `REVEAL_PER_HOUR*`).
- **Прогресс ученика** сервер не хранит отдельной копией: страница восстанавливает его из журнала попыток. Поэтому на любом устройстве он одинаковый, и подправить его в браузере нельзя. Избранное, заметки и цель на день хранятся на сервере тоже.
- **Смена кода.** Код приглашения меняется в настройках панели или командой `python server.py --invite НОВЫЙ`. Уже вошедшие ученики остаются в системе.
- **Смена пароля.** Пароль учителя меняется в настройках или командой `python server.py --password НОВЫЙ`.
- **Где хранятся данные.** Всё лежит в `trainer\server_data\trainer.db`. Для резервной копии достаточно скопировать этот файл.
- **Пересборка банка.** Если пересобрать банк (`build.py`), сервер подхватит новый сам, перезапуск не нужен.

**Откуда ученики могут зайти:**

- **Из той же сети** (класс, Wi‑Fi дома) — по адресу «Для учеников в сети». Компьютер с сервером должен быть включён. При первом запуске Windows спросит про брандмауэр: разрешите доступ в частной сети.
- **Из дома через интернет** сервер должен быть доступен снаружи. Можно арендовать недорогой VPS и запустить `server.py` там, скопировав папку Biblio или только `trainer`, если собрать банк с `--standalone`. Можно воспользоваться сервисом-туннелем, который даёт компьютеру внешний адрес.

Код приглашения защищает от посторонних, но ФИО — не пароль: кто знает код, может войти под любым именем. Для школьного тренажёра этого обычно достаточно.

## Банк ФИПИ с сайта OpenFIPI

`openfipi_parser.py` скачивает с https://openfipi.devinf.ru актуальные задания ЕГЭ (№ 1–27) из открытого банка ФИПИ вместе с ответами и складывает их в `Biblio\openfipi_bank`. Потом `build.py` сам добавит их третьим банком «ФИПИ».

```
python openfipi_parser.py            # задания, ответы, картинки и файлы к заданиям
python build.py
```

- **Первый запуск** занимает около 40 минут плюс скачивание файлов к заданиям (архивы для №24, 26, 27 бывают по 5–10 МБ). Парсер делает секундную паузу между запросами, чтобы не нагружать сайт автора.
- **Повторный запуск** берёт уже скачанное из кэша и докачивает только новое: новые задания, появившиеся ответы, недостающие файлы. Его можно прервать через Ctrl+C и запустить снова.
- **Ответы.** Берутся ответы, опубликованные на сайте. У заданий без ответа сайт показывает ответы пользователей, но они никем не проверены. Их можно включить ключом `--user-answers`: ответ засчитывается, если хотя бы двое дали одинаковый и он в большинстве. Такие задания подписаны «ответ пользователей».
- **Задания 20 и 21** на сайте ссылаются на игру из №19. Парсер подставляет условие №19 прямо в задание и исправляет номер, если сайт пометил №21 как «№ 20».
- **Картинки** вынимаются из текста в файлы. Решения, если они есть на сайте, показываются после ответа.
- **Дубли.** Задания, которые уже есть в `ege_bank` или `kompege_bank` (тот же номер, текст и ответ), в тренажёр второй раз не попадают.

Другие ключи:

```
python openfipi_parser.py --no-files        # без файлов к заданиям (останутся ссылки на сайт)
python openfipi_parser.py --only 5,17,24    # только эти номера
python openfipi_parser.py --max-pages 3     # проба на первых страницах списка
python openfipi_parser.py --refresh         # перекачать страницы заданий, а не брать из кэша
```

Отчёт парсера лежит в `openfipi_bank\report.txt`.

## Что проверить в report.txt после первой сборки

- **Таблица по номерам.** Сколько заданий каждого номера попало из каждого банка.
- **«Пропущено».** Задания без ответа или без номера. Их нельзя проверить, поэтому в тренажёр они не попадают.
- **«Не найдено локально».** Картинки и файлы, на которые есть ссылка, но которых нет на диске. Для картинок из ege_bank подставляется ссылка из `images_original`, для файлов КомпЕГЭ — ссылка на kompege.ru.
- **«Значения difficulty в КомпЕГЭ».** Сейчас 1 считается простой, 2 — средней, 3 и больше — сложной, 0 — «не указано». Если шкала другая, её легко поправить в `parse_level` в build.py.

## Как подбираются задания

Для каждого номера (1–27) и каждой темы внутри номера тренажёр ведёт «освоение» от 0 до 100%. Оно растёт от верных ответов и падает от ошибок, причём последние ответы весят больше старых.

- **Ошибка.** Можно попробовать ещё раз. Если и вторая попытка неверна (или нажато «Показать ответ»), показывается правильный ответ и ссылка на разбор, если он есть. Дальше:
  - похожее задание (тот же номер, по возможности та же тема) вернётся через 3 задания;
  - если тип решён верно, он повторится ещё через 1, 3 и 7 дней. Только после этого снимается с повторения;
  - само ошибочное задание вернётся через 2 дня.
- **Верно со второй попытки.** То же самое, но похожее задание вернётся через 5 заданий, а само задание — через 4 дня.
- **Режим «Все задания».** Номер выбирается с учётом слабости: чаще выпадают номера с низким освоением и те, что ещё не решали. Освоенные появляются редко, для поддержания.
- **Клик по номеру.** Тренировка только этого номера. Внутри него чаще выпадают слабые темы.
- **Сложность** подстраивается под освоение номера: сначала простые, потом средние и сложные (если у задания указана сложность).
- **Новые задания** в приоритете. Решённые возвращаются, только когда новые закончились.

Над заданием видно, почему оно выбрано: «Новое», «Повторение», «Работа над ошибкой», «Слабое место».

В боковой панели полоска под номером показывает освоение: красная — слабо, жёлтая — в процессе, зелёная — освоено (от 80% и не меньше 5 ответов). Оранжевая точка значит, что по номеру ждёт повторение.

Все числа (через сколько возвращать, пороги и т. д.) собраны в начале `app.js` (модуль `src/app/01-core.js`) в объекте `CFG`.

## Год и актуальность заданий

Формат ЕГЭ по информатике менялся, поэтому старые задания под тем же номером могут быть другого типа. По документам ФИПИ об изменениях КИМ:

| С какого года | Что изменилось |
|---|---|
| 2021 | Первый компьютерный ЕГЭ. Более ранние задания — другого формата. |
| 2023 | Новые типы у №6 (исполнитель «Черепаха») и №22 (параллельные процессы). |
| 2024 | Новый тип у №13 (IP-адреса и маска подсети). |
| 2025 | Новое №27 (анализ данных, кластеры). №16 и №19–21 расширены, старые задания для них годятся. |
| 2026 | По содержанию без изменений, поменялись только форматы файлов (.ods, .odt, .txt). |

Как это устроено:

- **Год экзамена** сборщик определяет в таком порядке:
  1. из подписи задания, например «Демоверсия 2021», «ЕГЭ-2024» или «Статград 26.10.2025»;
  2. иначе из даты появления на сайте (`createdAt` у КомпЕГЭ). Задания, добавленные с июля, относятся к экзамену следующего года.
- **Тип задания** для №6, 13, 22 и 27 дополнительно определяется по тексту условия. Например, «маска сети» в №13 — новый тип, «сколько различных путей» — старый. Если год неизвестен, решает текст.
- **Выбор периода.** В боковой панели есть переключатель:
  - «Актуальные» (по умолчанию) — без устаревших;
  - «С 2025 г.» и другие годы — только задания не старше выбранного года;
  - «Все, со старыми».
- **Приоритет свежих.** Среди актуальных заданий свежие выпадают чаще.
- **Устаревшие задания,** если их включить, помечаются «Старый формат» с пояснением. В прогнозе балла они весят в три раза меньше.
- **Задания без даты** (в `ege_bank` её нет) считаются актуальными. В режимах «С … г.» они не показываются, потому что год неизвестен.

Отчёт `report.txt` показывает, сколько заданий какого года в каждом банке и сколько устаревших по номерам. Если ФИПИ снова поменяет задание, добавьте номер и год в `CFG.formatSince` в `app.js`. Для отчёта то же самое прописано в `FORMAT_SINCE` в `build.py`.

## Задания 19–21

Три вопроса про одну игру показываются одной страницей: общее условие, вопросы 19, 20 и 21 и под ними три поля ответа, каждое со своим числом ячеек. В боковой панели им соответствует одна широкая карточка «19–21».

- **Проверка.** Каждый вопрос проверяется отдельно, на каждый даётся две попытки. Можно проверить все сразу или по одному. «Не знаю» показывает ответы на оставшиеся.
- **Статистика.** Для прогноза балла, освоения и журнала учителя 19, 20 и 21 остаются тремя разными номерами: на экзамене это три балла.
- **Как сборщик находит части одной игры:**
  - в банке ЕГЭ — по одинаковому условию;
  - в КомпЕГЭ — по подзадачам одного задания или по идущим подряд номерам;
  - в OpenFIPI — по ссылке на задание 19.

  Если у игры в банке есть только часть вопросов, на странице будут только они.

## Прогноз балла ЕГЭ

Вверху над заданием показан прогноз в тестовых баллах и диапазон, например «67 · 59–75». Прогноз появляется после 10 ответов. Клик по нему открывает подробный разбор:

- **Шансы:** на порог 40, на минимум для вузов 46 и на 80+.
- **Динамика:** изменение прогноза за неделю.
- **Где добрать баллы:** номера, которые ещё не решали, и самые слабые. Клик по номеру сразу открывает его тренировку.
- **График за 30 дней** с порогом 40; при наведении — балл на дату.
- **Таблица по всем 27 номерам:** шанс решить, число ответов, вклад в прогноз.

Как считается:

1. **Вероятность по каждому номеру.** Для номера оценивается вероятность решить его на экзамене с первой попытки. В расчёт идут последние 20 ответов по номеру:
   - свежие весят больше, а через месяц без практики вес ответа падает вдвое;
   - верный ответ на сложном задании и ошибка на простом весят сильнее;
   - ответ со второй попытки засчитывается на четверть, потому что на экзамене подсказки «неверно» нет;
   - задание, которое уже встречалось, весит втрое меньше: ответ мог запомниться;
   - ответы в варианте ЕГЭ весят в полтора раза больше: условия как на экзамене;
   - у №26 и 27 отдельно оценивается шанс на половину ответа (1 балл из 2);
   - пока ответов мало, оценка осторожная.
2. **Распределение первичных баллов.** Из вероятностей складывается распределение по 29 первичным баллам: задания 1–25 дают по 1, а 26 и 27 — 0, 1 или 2.
3. **Перевод в тестовые баллы.** Распределение переводится в тестовые баллы по шкале ЕГЭ‑2026. Диапазон покрывает 80% вероятных исходов.
4. **Ещё не решённые номера** считаются нерешёнными. Пока данные есть не по всем 27, у прогноза стоит звёздочка.

Параметры модели лежат в `CFG.forecast` в `app.js`. Шкалу перевода можно поменять в объекте `EGE` там же, когда выйдет шкала следующего года.

## Вариант ЕГЭ

Кнопка «Вариант ЕГЭ» в левой панели. 27 заданий (по одному на номер, 19–21 — одна игра) и таймер на 3 ч 55 мин. Ответы не проверяются до конца, вторых попыток нет, между заданиями можно переходить. Когда время выйдет, вариант завершится сам.

- **Подбор.** Задания нынешнего формата, по возможности новые для ученика и свежие.
- **Итог:** первичный балл из 29 и тестовый по шкале. За №26 и 27 засчитывается и половина ответа (1 балл из 2).
- **Ошибки** сразу ставятся на повторение, ответы идут в прогноз с повышенным весом.
- **Правильные ответы** показываются, только если над вариантом работали не меньше 20 минут. Иначе можно было бы получить ответы на 27 заданий, ничего не решая.
- **Лимит.** С сервером — не больше 3 вариантов в сутки на ученика.
- **Перерыв.** Можно уйти в тренировку и вернуться: ответы сохранятся, но время идёт. После перезагрузки страницы вариант продолжится.

## Уровни и достижения

- **Опыт (XP)** даёт сервер по журналу попыток, подкрутить его в браузере нельзя. За первое верное решение задания №1–10 начисляется 10 XP, №11–18 — 13, №19–23 — 15, №24–25 — 18, №26–27 — 22. Со второй попытки — половина, повторное решение того же задания — 2 XP. За каждые 5 решённых за день — ещё 15 XP. За вариант ЕГЭ — 30 XP и по 3 XP за первичный балл, если над ним работали не меньше 20 минут.
- **Уровни:** до 2-го нужно 100 XP, до 3-го ещё 200 и так далее. Звания: Новичок, Ученик (3), Кодер (5), Алгоритмист (8), Хакер (11), Гуру (15), Легенда (20).
- **18 достижений:** первое задание, 10/100/500/1000 решённых, 10 и 25 верных подряд, хардкор (10 заданий №24–27), полный набор номеров, работа над ошибками, марафон (50 за день), неделя и месяц занятий подряд, ночная смена и ранняя пташка, первый вариант, 80+ и 100 баллов.
- Плашка уровня — в левой панели; клик открывает все достижения с прогрессом и **рейтинг класса** (фамилия и инициал).
  Место в лиге и рейтингах дня, недели и месяца — по очкам за период (`rank_score`): (XP + заработанные ₿) / 2 × доля заданий
  без ошибок (ошибка — неверный ответ, решение со второй попытки или «Показать ответ» хотя бы раз в задании за период).
  Повышение и вылет в лиге по итогам недели считаются по тем же очкам; огонёк — по дням подряд. После ответа всплывает «+10 XP», при новом уровне — «LEVEL UP!», при новом достижении — карточка справа внизу.

## Python прямо на сайте

Кнопка **Python** рядом с номером задания открывает справа редактор. Это настоящий CPython (Pyodide), работает в браузере, на сервере ничего не выполняется.

- **Файлы задания** лежат рядом с кодом: `open('17.txt')`, `open('9.csv')` работают без скачивания. Для заданий с файлом редактор сразу подставляет заготовку с `open(...)`.
- **Библиотеки ЕГЭ:** math, itertools, functools, ipaddress, re, string, collections, fnmatch, sys и вся стандартная библиотека.
- **Подсветка кода** в цветах PyCharm: Darcula в тёмной теме, светлая схема в светлой. Размер шрифта меняют кнопки **A− / A+** или Ctrl + / Ctrl − в редакторе, выбор запоминается.
- **Черепашка (№6):** `from turtle import *` рисует на холсте под выводом. Рисунок сразу подогнан под фигуру, а не под сетку точек; линии толстые и яркие. Есть кнопки + / −, «по фигуре», «всё», двойной клик возвращает к фигуре. Колесо мыши и щипок тачпада меняют масштаб, перетаскивание и прокрутка двумя пальцами сдвигают. **«Сетка»** — точки с целыми координатами в шагах k (k определяется из кода сам), внизу координаты курсора в этих же шагах. **«⤢ крупно»** разворачивает рисунок на весь экран (Esc — свернуть). `tracer`, `update`, `done`, `dot`, `goto`, `up/down`, `circle`, заливка — как обычно.
- **Рекурсия (№16, 23):** `@lru_cache` и `@cache` подменены версией на чистом Python. Встроенная версия в браузере падает уже на 500 уровнях, эта держит 10 000+. Не забудьте `sys.setrecursionlimit(...)`, как и в обычном Python.
- **input()** берёт строки из поля «Ввод для input()».
- **Ctrl+Enter** — запустить, **■ Стоп** — прервать бесконечный цикл. Tab и Shift+Tab — отступ, Enter сохраняет отступ, после двоеточия добавляет новый.
- Код сохраняется сам для каждого задания в этом браузере. **«Прикрепить решение»** отправляет код учителю: в журнале у ответа появится ссылка «код». **«Открыть .py»** загружает файл с компьютера.
- В варианте ЕГЭ Python тоже доступен: на настоящем экзамене программировать можно.

Python скачивается с CDN jsDelivr при первом открытии (около 10 МБ, потом из кеша браузера). Если в школе CDN заблокирован, положите Pyodide на свой сервер — он подхватится сам:

## Биткоины и подарки

Биткоины (₿) зарабатываются трудом: обычно 1 ₿ за каждые 10 XP опыта (покупка заморозок огонька их не отнимает), а за каждые
25 впервые решённых заданий ученик получает случайный подарок «за труд». Курс плавает: раз в минуту сервер считает, сколько
учеников верно решали за последние 15 минут; до 10 человек — 10 XP за биткоин, каждые следующие 5 — ещё +1 XP, но не больше
20 XP (`BTC_RATE_*`). Курс записывается в таблицу `btc_rate`, и опыт переводится в биткоины по курсу на момент заработка —
уже заработанное не пересчитывается. В каталоге 70 подарков. Счётчик — в верхней панели, по клику — магазин:
подарок можно купить себе или однокласснику (ученику того же учителя), не больше 20 в сутки; «🎲 Случайный подарок»
выпадает любой, дорогие — реже (вес ∝ 1 / цена). Его цена — `GIFT_BOX_PRICE` (60 ₿) × индекс цен, но главный учитель может
задать свою во вкладке «Подарки» (от 5 до 5000 ₿, настройка `gift_box_price`; «Сбросить» возвращает стандартную).

За вариант ЕГЭ (сдан не быстрее 20 минут и с ненулевым баллом) кроме биткоинов за опыт начисляется бонус по тестовому баллу
(`EXAM_BTC`): 40+ — 15 ₿, 60+ — 30 ₿, 80+ — 50 ₿, 90+ — 100 ₿. Бонус считается для вариантов, сданных после выхода этой версии
(настройка `exam_btc_since`), и не начисляется за варианты в период использования лазейки.

За каждое впервые решённое задание (не быстрее минуты, ответ не подсмотрен) сверх биткоинов за опыт начисляется бонус по
номеру задания (`TASK_BTC`, со 2-й попытки — половина); ученикам таблицу не показываем — только «чем сложнее, тем больше».
Самостоятельная от учителя вместо этого оценивается как вариант (`work_btc`): полный вариант — по тестовому баллу, работа
короче — по проценту решённого и пропорционально размеру (N заданий из 27). Оба бонуса — с первого запуска версии
(настройка `task_btc_since`), задним числом не начисляются.

Экономика (константы — в `server.py`, блок «биткоины и подарки»):

- **Спрос.** Цена каждого подарка × (1 + 5 % за каждую покупку за неделю сверх средней по подаркам), от ×0,8 до ×1,5.
- **Термостат** (`econ`). Раз в сутки сравнивает средний кошелёк учеников, решавших что-то за 30 дней, с нормой
  (`ECON_TARGET` 500 ₿ или настройка `econ_target`) и сдвигает рычаги на `THERMO_STEP` (10 %) пути к цели — за неделю
  примерно наполовину: индекс цен ×0,8…2,5 (корень из полусуммы среднего и медианы к норме — пара «копилок» не делает
  дорого всем), множитель заработка ×0,5…1,3 (биткоины за опыт, бонусы за задания, варианты и самостоятельные; денег много —
  меньше), комиссия рынка 5–20 %. Рычаги хранятся в таблице `thermo` с моментом начала действия: биткоины считаются по
  множителю на момент заработка (`earn_at`), смена рычагов прошлое не трогает. Первый запуск стартует с прежнего индекса
  (средний кошелёк / норма, ×1…10), заработка ×1 и комиссии 10 %. Раз в неделю (по понедельникам, настройка `thermo_week`):
  плата за хранение `TAX_RATE` (3 %) с суммы больше `TAX_FROM` нормы (800 ₿) — в банк; когда средний кошелёк меньше
  0,6 нормы — стипендия из банка (до 40 ₿, не больше 10 % банка на всех) решившим 10+ заданий за неделю с кошельком меньше
  нормы; когда больше 1,3 нормы — лимитка недели. В ручном режиме (настройка `thermo_mode`) рычаги ставит главный учитель
  (`POST /api/admin/thermo`, пределы — `THERMO_SET`), плата за хранение идёт, стипендии и лимитки сами не запускаются.
- **Банк рынка** (таблица `bank`, старт `BANK_START` 10 000 ₿). Приходит `LABOR_BANK` (50 %) от заработка учеников трудом
  (`labor_accrue`: опыт, бонусы за задания, варианты и самостоятельные — по дням с запуска версии, последние `LABOR_DAYS` дней
  досчитываются при каждом пересчёте экономики; у учеников ничего не списывается), комиссия рынка, плата за хранение, снятое
  учителями, комиссия с остальных операций с подарками (`op_fee`: покупка, «🎲», лимитка, улучшение — четверть комиссии
  рынка, не больше `OP_FEE_MAX` 5 %, вниз до целого; цена не меняется — эта доля идёт в банк, а не сгорает) и 10 % с продажи
  сразу (`SELL_SHARE`); в журнале банка — строкой за день; уходят начисления
  учителей (больше, чем в банке, начислить нельзя) и стипендии. Главный учитель пополняет банк
  или изымает из него (`POST /api/admin/bank`). Журнал банка виден всем учителям (имена — только своих учеников).
- **Ученикам — без процентов.** Комиссии и проценты экономики ученикам не показываются: только итоговые суммы («получишь N ₿»,
  «продать сразу за N ₿»), множители цен и заработка и банк рынка; проценты — в панели учителя.
- **Лимитка недели** (`LIMITED`, таблица `limited`): особый подарок на 7 дней тиражом `LIMITED_CAP` (30) по
  `LIMITED_PRICE` × индекс; в каталоге и «🎲» его нет, улучшить нельзя, своя редкость «Лимитка». Выходит та, что выходила
  реже всех; главный учитель может запустить или остановить её сам.
- **Уникальность.** Улучшение делает подарок уникальным: номер и случайные фон (31), узор (31), эффект (18) и поза (9);
  сочетание у одного вида не повторяется. Тираж — `UNIQ_CAP` (100) на вид; проданные не возвращаются. Цена улучшения —
  (`UP_BASE` 350 + `UP_SHARE` 60 % каталожной цены) × (1 + 1 % за каждый уже выпущенный уникальный этого вида) × индекс цен,
  шаг 5 ₿: Печенька — от 355 ₿, Замок — от 1010 ₿.
- **Продажа сразу.** Подарок сгорает. Цена — за сколько подарок достался владельцу (`gifts.paid`: в магазине — заплаченное,
  на рынке — цена сделки, из «🎲» — нынешняя цена выпавшего в момент выпадения; от учителя и за труд — NULL, тогда нынешняя цена
  без надбавки за спрос), но не дороже нынешней цены в магазине: иначе выгодно скупить одинаковые, поднять спрос и сдать дороже.
  У уникального — плюс доля базовой цены улучшения (без надбавки за тираж) по редкости (редкий 0,45, эпический 0,9,
  легендарный 2,2, мифический 6). Ученику — `SELL_SHARE` (90 %), остальное — в банк рынка; в среднем улучшение убыточно
  (продажей возвращается ≈ 0,78 его цены). Прежним подаркам `paid` заполнен один раз по журналу покупок.
- **График цены.** `GET /api/gifts/price?gift=…` — цена подарка в магазине за `PRICE_DAYS` (30) дней: на конец каждого дня —
  каталог × индекс цен термостата в тот момент (до термостата — из `econ_hist`) × спрос по покупкам за `DEMAND_DAYS` до него
  (`gift_price_hist`, пересчёт раз в 5 минут), последняя точка — цена сейчас; в каждой точке — сколько купили за неделю.
  У лимитки графика нет. В шторке подарка — линия с подсказкой; «Кому подарить» — поиск по имени.
- **Рынок.** Ученик выставляет свой подарок за свою цену (`MARKET_MIN`–`MARKET_MAX`, не больше `MARKET_MAX_LISTED` сразу),
  одноклассники (ученики того же учителя) покупают; уникальный переходит со своим номером и свойствами. Продавцу — цена минус
  комиссия термостата (5–20 %), комиссия уходит в банк рынка. Подарок, выпавший в «🎲» (`gifts.kind = 'box'`: куплен учеником
  или подарен учителем «🎲 случайным»), при первой продаже — с комиссией `MARKET_FEE_BOX` (50 %), чтобы не было выгодно
  покупать «🎲» и перепродавать дорогие выпадения; прежние покупки «🎲» размечены один раз — заплачено меньше 60 % каталожной
  цены выпавшего. Пока подарок на рынке, его нельзя улучшить или продать сразу. Подарки за труд
  считаются по первому владельцу (`gifts.first_sid`) — продажа на рынке не даёт получить их заново.
- **Без халявы.** Верный ответ быстрее 30 секунд — минус 1 ₿ (`BTC_FAST_MS`; как «быстрее минуты — минус опыт»,
  действует с первого запуска версии, задним числом не штрафует). На долгие задачи — своё минимальное время
  (`HARD_MIN_MS`: №24 — 10 минут, №25 — 5, №26 — 20, №27 — 25; с настройки `hard_min_since`): быстрее — −1 XP и −1 ₿,
  задание не засчитано решённым. Учитель может снять биткоины (не больше, чем есть)
  и удалить подарок из профиля ученика — подарок сгорает.
- **Редкость** считается по шансам и видна на подарке: у обычного — шанс выпасть в «🎲», у уникального — шанс сочетания
  фон × узор × эффект («1 из N»).

Окно «Биткоины» (по клику на счётчик ₿) устроено как приложение: шапка с балансом и «?» (правила и экономика — в шторке),
вкладки снизу — «Магазин» (полка своих подарков, лимитка, сетка подарков: значок и цена), «Рынок», «Мои», «Forbes» и «История».
Нажал на свой подарок — снизу шторка с кнопками «Улучшить», «Продать» и «На рынок» (цена — там же); на подарок в магазине —
«Купить» или «Подарить» (кому — в шторке); на предложение рынка — «Купить».

**Forbes класса** (`/api/forbes`, `forbes_data`): среди учеников одного учителя. Состояние — биткоины + оценка подарков (сколько
дадут, если продать все сейчас); рост за неделю — по снимкам `forbes_hist` (пишутся при каждом пересчёте и раз в день для всех
классов); «рывок недели» — самый большой рост, «новичок» — в тренажёре меньше 14 дней. Вкладки: состояние (номер один — на
«обложке»), самый дорогой подарок, самая дорогая коллекция (только подарки) и самая редкая коллекция (очки редкости `RARE_SCORE`:
уникальные — 4…100, лимитка — 8, обычные — 0…3). Первые 10 и сам ученик, если он ниже; строка открывает профиль.

Профиль: шапка с уровнем и кольцом прогресса до следующего уровня; если у ученика есть уникальные подарки, шапка — в цветах
и узоре самого редкого из них, а до 6 уникальных (сначала редкие) летают вокруг уровня. Ниже — огонёк, короны, победы в
дуэлях и оценка подарков, затем вкладки «Подарки / Награды / Достижения» (неполученные награды свёрнуты). В окне подарков и в профиле — оценка подарков (`gift_value`): сколько дадут, если продать все сейчас, сколько такие стоят в
магазине (нынешняя цена, у уникального — плюс 500 ₿ улучшения) и три самых ценных.

Во вкладке «Экономика» сверху — термостат и банк рынка (`thermo_info`): рычаги сейчас и куда их тянет, лимитка, журнал банка
и история рычагов, у главного учителя — ручной режим, норма кошелька, лимитка и пополнение банка. Дальше — графики рынка всего
сайта как в модели экономики (`market_hist`): средний кошелёк и медиана с полосой нормы, цены и заработок, заданий на средний
подарок, покупки, банк и комиссия — по неделям за 26 недель или по дням за 30, с событиями (раздачи, плата за хранение,
стипендии, пополнения банка, ручная настройка) и лимитками; кошельки прошлых дней восстанавливаются от нынешних назад по
движениям биткоинов. Ниже — графики ваших учеников за 30 дней (`econ_charts`): пришло и ушло по дням, биткоины на руках, подарки по дням,
курс биткоина и индекс цен (история индекса — таблица `econ_hist`), с таблицей по дням; ниже — откуда пришли и куда ушли биткоины учеников, подарки по редкости, самые большие кошельки и журнал
изменений в профилях (покупки, улучшения, продажи, начисления и снятия, подарки от учителя и за труд, удаления); по клику на
имя — кошелёк, подарки и история ученика. Учитель во вкладке «Подарки» видит цены, заработок, банк и выпуск, дарит подарок (или случайный, можно сразу уникальный) и начисляет
биткоины ученику, классу или всем сразу. Подарки видны значками у ника в рейтинге и витриной в профиле.

## Курс «Программирование для ЕГЭ» (закрытый)

Отдельный раздел с кнопкой в левой панели. Как и «Курс», открывается по паролю: главный учитель задаёт его во вкладке
«Программирование» панели учителя (в коде пароля нет: в базе хранится только его хеш), ученик вводит его один раз.
Пока пароль не задан, курс закрыт у всех учеников; учителю он открыт всегда. Основы Python и темы по номерам ЕГЭ; в каждой — уровни от базы до максимума:
слайды с примерами (их можно запустить) и задачи. Ответ проверяет сервер; следующий уровень открывается, когда решена половина задач.

Курс собирается из описаний в `tools/pycourse/m*.py`:

    python3 tools/build_pycourse.py          # все темы
    python3 tools/build_pycourse.py m17      # одна тема

Сборщик генерирует файлы с данными (одинаковые при каждой сборке), запускает эталонное решение каждой задачи и берёт ответ из его вывода —
ответы руками не пишутся. Результат — папка `pycourse/`: уроки с ответами (их отдаёт только сервер) и `pycourse/data/` с файлами задач.

## Решения к заданиям

- **Решение ученика.** Кнопка «Прикрепить решение» в редакторе Python. Учитель видит ссылку «код» в журнале ученика рядом с ответом.
- **Решение учителя.** В панели учителя откройте любое задание (клик по заданию в журнале, ленте или подборке). Внизу есть поле «Ваше решение»: код или объяснение. Ученики увидят его после того, как ответят на задание, рядом с правильным ответом. Чтобы удалить, очистите поле и сохраните.

## Избранное, заметки, поиск, цель на день

- **☆ рядом с номером задания** — добавить в избранное. Кнопка «Избранное» в левой панели — тренировка только по избранным.
- **✎ Заметка** — заметка к заданию (идея решения, где ошибся). Сохраняется сама.
- **Поиск** внизу левой панели: номер задания с kompege.ru (или ссылка на него), код задания ФИПИ, id из журнала учителя.
- **Цель на день.** Наверху справа «Сегодня 7 / 20» с полоской; клик — выбрать цель (10, 20, 30, 50 или без цели). **серия N дней** — сколько дней подряд цель выполнена.

## Прогресс

Без сервера прогресс хранится в браузере на этом компьютере (localStorage). Он переживает перезапуск браузера, но не переносится на другое устройство. Чтобы перенести, внизу боковой панели есть «Сохранить прогресс в файл» и «Загрузить прогресс». Тем же файлом ученик может поделиться с учителем.

Если на одном компьютере занимаются несколько учеников, у каждого должен быть свой профиль браузера.

С сервером прогресс строится из журнала попыток на сервере и одинаков на всех устройствах. Кнопки «Загрузить прогресс» и «Сбросить прогресс» в этом режиме скрыты: журнал видит учитель, подменить его нельзя.

## Оформление

- **Игровой стиль Egeshka.** Скруглённые карточки и «объёмные» кнопки, которые вдавливаются при нажатии: зелёный — действие, голубой — выбранное, жёлтый — уровень. Шрифт Nunito лежит в `vendor/fonts`, интернет для него не нужен.
- **Светлая и тёмная тема.** По умолчанию как в системе; кнопка ☀/☾ в левой панели (и в панели учителя) переключает вручную, выбор запоминается.
- **Телефон.** Номера заданий свёрнуты в кнопку вверху экрана — задание сразу на первом экране. После выбора номера панель сворачивается сама.
- **Клавиатура.** Enter — проверить / следующее задание, Esc — закрыть окно. Видимая рамка фокуса при работе с клавиатуры.
- Ссылки на файлы, которые дублируют кнопки «Файлы к заданию», из текста условия убираются.

## Ответы

- Регистр букв и буква «ё» не важны.
- Если ответ состоит из нескольких чисел (17, 18, 20, 26, 27), показываются отдельные ячейки.
- Если ответ — таблица (25), показывается таблица на 10 строк, как в КЕГЭ; лишние строки остаются пустыми.
- В таблицу можно вставить весь ответ из буфера обмена одним Ctrl+V: строки через перенос, числа через пробел.
